**HyprDarwin 0.2.2** makes the app log useful. If tiling, a reload or a permission "did nothing", the answer is now one `tail` away.

## The app log

```sh
tail -f ~/Library/Logs/hyprland-darwin/hyprdarwin.log
```

Until now this file was written only on two rare failures, so it usually didn't exist and `tail` found nothing. It now records:

- **Startup:** the HyprDarwin version and the macOS version.
- **Every config reload:** which file was loaded, whether it was applied, and each error and warning, the same lines as the diagnostics window.
- **Permission changes:** when Accessibility is revoked (tiling pauses) or granted again (tiling resumes).

```text
2026-10-02T23:14:39Z HyprDarwin 0.2.2 (abc1234) started, macOS Version 27.0.1 (Build 26A434)
2026-10-02T23:14:39Z config: loaded /Users/you/.config/hyprland-darwin/config.toml with 1 error(s), 0 warning(s)
2026-10-02T23:14:39Z config:   [ERROR] bar.height: Must be in [16, 100] range
2026-10-02T23:20:02Z permissions: Accessibility revoked, tiling paused
```

Plugin logs stay where they were, one file per plugin: `~/Library/Logs/hyprland-darwin/<name>.log`.

## Upgrade

```sh
brew upgrade --cask hyprdarwin
```

> [!IMPORTANT]
> Releases are signed ad hoc (no Apple Developer ID), so macOS asks for **Accessibility** again after an upgrade. In **System Settings → Privacy & Security → Accessibility**, remove HyprDarwin with **−**, add it back, then relaunch. Your config is untouched.

## Assets

`HyprDarwin-0.2.2.zip` contains `HyprDarwin.app`, the `hypr` CLI, `shell-completion/` (zsh, bash, fish) and `manpage/`. It needs macOS 13 or newer, on Apple Silicon or Intel.

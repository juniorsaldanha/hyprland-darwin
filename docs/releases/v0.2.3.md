**HyprDarwin 0.2.3** fixes windows overlapping on a workspace that was busy when HyprDarwin started.

## Fix: overlapping windows after startup

At startup, if the focused workspace held more than 3 windows, HyprDarwin switched its root container to the accordion layout. That ignored `default-root-container-layout` from your config, and the workspace kept the accordion layout (windows stacked on top of each other with a peek of padding) even after you closed windows. Moving the windows to another workspace tiled them correctly, because the other workspace still had a tiles container.

HyprDarwin no longer overrides the layout at startup. Workspaces use `default-root-container-layout`, and you can still switch a workspace explicitly:

```sh
hypr layout --workspace 1 --root tiles
```

If a workspace is already stuck in accordion from an earlier run, run the command above once.

## Upgrade

```sh
brew upgrade --cask hyprdarwin
```

> [!IMPORTANT]
> Releases are signed ad hoc (no Apple Developer ID), so macOS asks for **Accessibility** again after an upgrade. In **System Settings → Privacy & Security → Accessibility**, remove HyprDarwin with **−**, add it back, then relaunch. Your config is untouched.

## Assets

`HyprDarwin-0.2.3.zip` contains `HyprDarwin.app`, the `hypr` CLI, `shell-completion/` (zsh, bash, fish) and `manpage/`. It needs macOS 13 or newer, on Apple Silicon or Intel.
